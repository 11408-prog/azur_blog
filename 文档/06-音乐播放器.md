# 06 音乐播放器（本地 mp3 方案）

## 为什么不用在线 API

`musicConfig.ts` 支持 `mode: "meting"`（在线拉歌单），但实测**不可用**：

- 模板自带的 `meting.mysqil.com` 已下线，DNS 都解析不了
- 酷狗（kugou）虽然能通过 `api.kfjie.me` 拉到歌单，但音频会 302 到 `fs.youthandroid2.kugou.com`，**该 CDN 的 SSL 证书失效**，浏览器必然拦截
- 网易云走 `api.kfjie.me` 是正常的（实测能下到音频），但目前没用

所以改成 **`mode: "local"` + 本地 mp3**。

## 同步脚本

```bash
pnpm sync-music                              # 增量同步
node scripts/sync-music.mjs --dry            # 只看会改什么，不写盘
node scripts/sync-music.mjs --limit 5        # 调试，最多处理 5 首
node scripts/sync-music.mjs --online-only    # 连不上就静默跳过（构建时用）
```

流程：拉歌单 → 按歌曲 hash 与清单 diff → 只下载新增、删除已移除 → 写清单 → 生成播放列表。
歌单 ID 默认取自 `KUGOU_PLAYLIST_ID` 环境变量，没有则用脚本里的默认值（与 `musicConfig.ts` 里的 `id` 一致）。

`prebuild` 串联了 `--online-only`，所以**断网构建不会失败**，联网时会顺带同步。

## 文件位置

| 文件 | 是否入库 | 说明 |
| --- | --- | --- |
| `public/music/*.mp3`、`public/music/cover/*` | **否**（已 gitignore） | 体积大，用脚本重建 |
| `scripts/music-manifest.json` | 是 | 清单，记录已同步了哪些歌 |
| `src/components/widgets/music-player/localPlaylist.generated.ts` | **是（必须）** | 播放列表，`constants.ts` 会 import 它，丢了构建会报错 |
| `public/assets/music/url/*.mp3` | 否（已 gitignore） | 模板自带的 4 首示例歌，站点没有任何地方引用，部署脚本也会剔除 |

**换机器时**：重跑 `pnpm sync-music` 即可。即使清单丢了，脚本会扫描 `public/music/` 里已有的 mp3（文件名就是 hash）自动补录，不会重复下载。

## 三个安全设计（改脚本时别破坏）

1. **异常保护**：远程歌单数量异常地少（少于本地的一半）时，判定为接口异常，**直接中止，不删任何文件**
2. **自愈**：清单丢失但 mp3 还在时补录，不重复下载
3. **绝对路径**：播放列表里的 url 写 `/music/xxx.mp3`（带前导斜杠），并在 `constants.ts` 里过 `withBase()`。模板原示例写的是相对路径，进了文章页 `/posts/xxx/` 会拼错导致 404

## 事故复盘：脚本曾经删掉过 25 个 mp3

调试时用了**无效的 `PLAYLIST_ID` 模拟断网**，接口没有报错，而是**返回了 1 首假数据**。脚本照常 diff，判定另外 37 首"已移除"，于是删掉 25 个 mp3 并清空清单。

教训（已写进脚本，别改回去）：

- 接口失败 ≠ 返回空，也可能返回少量假数据，所以必须有"数量骤降"的异常保护
- 删文件前先判定远程结果可信度，不可信就中止
- 清单和 mp3 要能互相自愈，任一方丢失都不能导致重复下载

## 酷狗歌单 ID 是怎么来的

`musicConfig.ts` 里写的是 `collection_3_2586463630_2_0`，不是分享短链。酷狗概念版的分享链接（`https://t1.kugou.com/xxx`）会 302，跟随重定向后拿 `global_specialid`，拼成 `collection_3_<id>_2_0` 才是有效 ID。**直接把短链传给 API 会返回"未知歌曲"。**

## 已知情况

- 歌单里个别歌可能 404（版权下架），脚本会跳过并在下次重试
- 文件名用歌曲 hash 而不是歌名，避免日文 / 中文歌名在 Windows 上的编码问题
- 时长由 MP3 帧头估算，CBR 准确，VBR 有误差
- **脚本开头有 `process.env.NODE_TLS_REJECT_UNAUTHORIZED = "0"`**，会在整个脚本进程里**关闭 TLS 证书校验**。当初是因为作者本机的 schannel 坏了（见 [10](./10-排障与环境问题.md)），Node 侧也要放宽才能连上 API。如果你的环境没有这个问题，建议删掉这一行，避免下载内容被中间人篡改
- **体积（2026-11-03 实测）**：本地 mp3 41 首约 157 MB，是整个 `dist/`（337 MB）的一半以上。但**不影响首屏**——首页 HTML 没有 mp3 引用，浏览器只在点播放时加载单曲（最大 11 MB）。想减肥的方向是转码降码率或砍歌单，这是内容决策，不是技术问题
- 歌曲内容的版权归权利人所有。公开仓库不要提交 mp3（已经 gitignore）；GitHub Pages 上公开提供整份歌单下载同样有风险，请自行评估
