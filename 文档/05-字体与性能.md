# 05 字体与性能

## 字体子集化

**背景**：自定义字体 ZenMaruGothic（1.5 MB）和 Loli（4.7 MB）曾占首屏开销的 97.7%（手机 4G 下约 70 秒）。
2026-11-03 已经子集化为约 519 KB + 320 KB，观感不变（同一款字体，只裁掉没用的字），体积减少约 87%。另有两个配置里无引用的 `.ttf`（14.5 MB）是死文件，已移入备份。

**机制**：

- 正文字体顺序是 `--font-sans: ZenMaruGothic → Loli → 系统字体`，逐字符回退
- ZenMaruGothic 是日文字体，**不含简体简化字**（"灵毙线欢关记链归"等），这些字由 Loli 渲染
- 所以 Loli 子集只装"ZenMaru 缺的字"（1548 个），装重复的字是纯浪费
- 兜底策略：子集含 GB2312 一级常用 3755 字、全角符号、ASCII 和全站实际出现的字符（共 4623 字）。日常写文章不会缺字，只有极生僻字会临时变成系统字体

**当前文件**：`src/assets/fonts/ZenMaruGothic-Medium.woff2`、`src/assets/fonts/loli.woff2`。

**以后新增文章出现个别字变样**，需要重新子集化。子集化脚本是作者本机上的 Python 脚本（依赖 `fontTools` 和 `brotli`），**不在仓库里**；
仓库里的 `pnpm prepare-fonts`（`scripts/prepare-fonts.mjs`）只负责把 `ttf` 转成 `woff2`，不做子集化。

**不要改字体模式**：`siteConfig.ts` 的 `font.mode` 保持 `"custom"`。想临时试系统字体，用环境变量 `MIZUKI_FONT_MODE=system` 跑 dev，不改配置。

**回滚**：把备份的原版 woff2 拷回 `src/assets/fonts/` 即可。

构建后字体引用由 `scripts/check-font-loading.mjs` 检查（`pnpm check-fonts`）。

## 线上"慢 / 点了没反应"怎么排查

规律：**先用 `curl` 分资源测大小（gzip 后），再猜原因**，别凭感觉归因（"HTML 356 KB 很大"其实 gzip 后只有 62 KB，不是瓶颈）。

1. **手机端点了像没反应**：查 `astro.config.mjs` 的 Swup 配置，`preload` 应为 `true`（视口内链接后台预取），`progress: true` 让切换有顶部进度条。曾经 `preload: false`，导致点击后才开始抓页面、等待期零反馈（2026-11-03 踩过）
2. **首屏巨慢**：先查字体。`loli.woff2` 曾经 4.7 MB 且带 preload 阻塞渲染；再查页面引用的其他大资源
3. **点进某页才慢**：看该页特有的资源。相册页查原图体积，音乐播放查单曲大小
4. **"改完没生效"的假象**：Swup 无刷新导航有内存缓存，用 `Ctrl+F5` 或无痕窗口对照验证，别急着怀疑构建

**体积事实（2026-11-03）**：

- 首屏实际传输（gzip 后）：HTML 62 KB + CSS 46 KB + JS 45 KB ≈ **153 KB**（不含字体时很轻）
- 字体原占 97.7%，已通过子集化解决
- **音乐不阻塞首屏**：首页 HTML 里没有 mp3 引用，只有点击播放才加载单曲。但 `dist/` 总体积大头就是音乐
- 相册图片只影响相册页（已有懒加载）。`tools-convert-albums.mjs` 可以把相册图转成 webp（见 [11](./11-迁移记录与待办.md)）

## 国内访问慢：托管方案评估档案

背景：手机端"点不开任何东西、点了没反应"，系统性排查了托管平台和资源体积。以下是 2026-11-03/04 的实测，**数据波动大，请看相对值**。

| 目标 | TTFB / 延迟 |
| --- | --- |
| `11408-prog.github.io/azur_blog` | 0.82 ~ 4.07 秒（多次测量波动） |
| Cloudflare 边缘 `1.1.1.1` | ping 143 ms，下载 1 MB 仅 90 KB/s |
| `pages.dev`（Cloudflare Pages） | 11.77 秒 |
| `vercel.app` | 12.16 秒 |
| 腾讯云香港轻量（厂商和第三方实测） | 广州 10~20 ms，北京 40~55 ms，晚高峰稳定 |
| 模拟手机弱网（限速 200 KB/s）访问本站 | TTFB 3.6 秒 |

| 平台 | 结论 | 原因 |
| --- | --- | --- |
| GitHub Pages（现状） | 保留，境外平台里已经是最快的 | 走 Fastly，但国内链路慢且波动 |
| Cloudflare Pages / CDN | ❌ 不可取 | 免费版大陆无节点，实测比 github.io 慢 7 倍 |
| EdgeOne Pages（腾讯） | ❌ 当前不可用 | 无自定义域名时，大陆可用区只给 3 小时有效的预览链接；含大陆的自定义域名必须 ICP 备案。没有备案域名就比 github.io 还差 |
| Gitee Pages | ❌ 已下线 | 2024-05 下线，官方明确暂无恢复计划 |
| Netlify | 3.6 秒，不如现状 | |
| 云服务器（大陆机房） | ✅ 最快但要备案 | 域名须国内注册 + 实名 + 服务器满 3 个月 + 管局审核 5~20 个工作日；个人备案名称不能带"博客"等词 |
| **云服务器（香港机房）** | ✅ **推荐路线：免备案** | 延迟 30~65 ms；入门 2 核 2G 约 ¥38/月，锐驰 2 核 1G 约 ¥40/月；入门型可免费试用 1 个月先实测 |

**已做的代码侧提速**：字体子集化（6.2 MB → 0.84 MB）；Swup `preload: true` + `progress: true`。

**决策状态**：目标是"国内变快"。Cloudflare 已否决；香港服务器方案已讲清（Caddy 托管 + rsync 部署，保留 `/azur_blog` 前缀就不用改 `base`），**等待决定是否购买或试用**。价格和政策可能已变化，购买前请重新核对。
