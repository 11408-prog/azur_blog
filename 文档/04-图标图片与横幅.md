# 04 图标、图片与横幅

## 图标（Iconify）

配置文件里的图标一律用 Iconify 格式 `集合名:图标名`。本地已捆绑 **6 个集合**，离线可用：

| 集合 | 图标数 | 用途 |
| --- | --- | --- |
| `material-symbols` | 16276 | Google 通用图标（主页、搜索、设置……） |
| `mdi` | 7638 | Material Design Icons |
| `fa7-solid` | 2000 | Font Awesome 实心 |
| `fa7-regular` | 272 | Font Awesome 线框 |
| `fa7-brands` | 608 | FA 品牌（github、qq、weibo、weixin、bilibili、x-twitter……） |
| `simple-icons` | 3723 | 品牌 logo（bilibili、pixiv、tiktok、neteasecloudmusic、xiaohongshu、zhihu……） |

### 两条红线

1. **不能用 `logos:`、`devicon:` 等其他前缀**。它们走运行时 `<iconify-icon>` 组件，写在配置文件里构建必挂。配置文件只能用上面 6 个。
2. **网页版 Iconify 能搜到 ≠ 本地有**。要么没装那个集合，要么装了但版本没收录该图标（酷狗就是后者）。**以本地查询为准**。

已知没有的：酷狗 `kugou`（改用 `fa7-solid:music`）、抖音 `douyin`（改用 `simple-icons:tiktok`）、QQ 音乐。
确认有的：`simple-icons:pixiv`、`simple-icons:bilibili`、`simple-icons:neteasecloudmusic`、`simple-icons:xiaohongshu`、`simple-icons:zhihu`、`simple-icons:wechat`、`fa7-brands:qq` / `weibo` / `weixin`。

### 怎么查某个图标本地有没有

```bash
node -e "const d=require('./node_modules/@iconify-json/simple-icons/icons.json');
console.log([...Object.keys(d.icons||{}),...Object.keys(d.aliases||{})].filter(x=>x.includes('kugou')))"
```

改集合名和关键字即可。

### 图标名写错：不是"不显示"，是构建失败

写了不存在的图标名（比如 `simple-icons:kugou`），`pnpm build` 会直接失败：

```
[ERROR] Error: Unable to locate "simple-icons:kugou" icon!
[ERROR] [build] Caught error rendering /404: ...
```

报错会挂在 `/404` 页面上，因为 404 页也渲染资料卡，排查时别被误导。
根因是 `src/plugins/astro-icon-include.mjs` 扫描 `src/` 里的 `前缀:名字` 字符串，只认那 6 个本地集合，不存在的名字进不了白名单，渲染时报错。

### 新增图标名必须重启 dev

在 `navBarConfig.ts`、`profileConfig.ts`、`ai-tools.ts` 里写了一个**之前没用过**的图标名，页面会报 `Unable to locate "mdi:puzzle" icon!`。

原因是上面那个插件只在 `astro.config.mjs` **加载时**扫描一遍，热更新不会重新跑。**改完图标名后重启 dev**（`Ctrl+C` 再启动），不是配置写错了。
优先复用已经出现过的图标名：`simple-icons:deepseek`、`simple-icons:openai`、`simple-icons:claude`、`fa6-brands:*` 系列。

## 浏览器标签页图标（favicon）

两步：图片放进 `public/favicon/`，再在 `siteConfig.ts` 的 `favicon` 数组里指向它。

```ts
favicon: [{ src: "/favicon/favicon.png", sizes: "64x64" }],
```

- 数组**留空**则用模板默认（`src/constants/icon.ts` 里的 `/favicon/favicon.ico`）；填了 png 就不会再用那个 ico
- 渲染逻辑在 `src/layouts/partials/HeadTags.astro`
- 支持 `theme: 'light' | 'dark'`，可以为深浅色各放一张
- 推荐 64×64 或 32×32，PNG / ICO 都行

换了图看不到新图标？浏览器对 favicon 缓存很顽固，用 `Ctrl+Shift+R` 强刷，还不行就开隐私窗口。

## 顶栏左上角的图标

顶栏「Ghost」文字左边的小图在 `navbarTitle` 里配，**和 `favicon` 是两回事**：

```ts
navbarTitle: {
  mode: "text-icon",             // 图标 + 文字；改 "logo" 则只显示整张 logo
  text: "Ghost",
  icon: "/favicon/favicon.png",  // 那个小图
  logo: "assets/home/default-logo.webp", // mode 为 logo 时才用
},
```

**webp 回退**：如果 `icon` 以 `.png` 结尾，`Navbar.astro` 会自动把 `.png` 换成 `.webp` 作为优先加载的 `<source>`，png 兜底。所以用了 png 就要在同目录备好**同名 `.webp`**
（`sharp('x.png').webp().toFile('x.webp')`），否则浏览器每次都会先 404 一次再回退。`logo` 字段同理。

### 只想显示文字、不要图标

模板原生只有 `text-icon` 和 `logo` 两种 mode，没有"纯文字"，所以改了 `Navbar.astro`（图标渲染加了一层 `iconSrc ?` 判断）。
现在配置里把 `icon` 留空即可：

```ts
navbarTitle: { mode: "text-icon", text: "Ghost", icon: "", logo: "..." },
```

> 这是改了模板源码，升级 Mizuki 时会被覆盖，要重新打补丁（见 [02](./02-项目结构与配置速查.md)）。

## 站点运行天数

侧边栏「站点统计」里的运行天数，起点由 `siteConfig.siteStartDate` 决定（当前 `2026-08-11`，即首篇博文发布日）。

- 数字在**浏览器端**计算（`SiteStats.astro` 底部的内联脚本），不是构建时写死的，不用重新构建每天也会 +1
- 已改成**按自然日**计算（两端归零到当地 00:00）。模板原版用 `Math.ceil` 且带时分秒，会虚高 1 天
- 想改起点就改这一个字段；想和旧站衔接，就填旧站首篇博文的日期
- 「最后更新」不读这个字段，它按最新文章的 `published` 自动算

## 首页横幅轮播图

涉及**三处**，缺一处都可能"换了图没生效"：

| 位置 | 作用 |
| --- | --- |
| `public/assets/desktop-banner/`、`public/assets/mobile-banner/` | 对外公开的那份 |
| `src/assets/public/assets/desktop-banner/`、`.../mobile-banner/` | **影子副本**，Astro 图片优化通道读它 |
| `siteConfig.ts` 的 `banner.src` | 引用路径 |

```ts
banner: {
  src: {
    desktop: ["/assets/desktop-banner/1.webp", "…/2.webp", "…/3.webp", "…/4.webp"],
    mobile:  ["/assets/mobile-banner/1.webp", ...],
  },
  position: "center",                       // 裁剪位置：top / center / bottom
  carousel: { enable: true, interval: 3 },  // 开关 + 每张停几秒
},
```

- **数组多于 1 张才轮播**。只想要一张静态横幅，就只留一个
- 桌面和移动端分开配置。竖屏手机用 `mobile`，建议配竖版图，否则横图居中裁切会很窄
- 渲染文件是 `src/components/layout/Banner.astro`，自带缓慢缩放和淡入淡出
- 模板的旧图备份在各自目录的 `.template-backup/`
- **别把图放进 `src/assets/public/...` 以外的嵌套位置**，正确的是项目根下的 `public/assets/...`（外加影子副本）

### "换了图却没生效"的两个根因

**1. 影子副本（最常见）**。Mizuki 为了用 Astro 的 `<Image>` 做优化，约定 `public/` 下的每张图可以在 `src/assets/public/` 下放一份同名副本。
`src/utils/image-source-utils.ts` 的 `resolveImageMetadata()` 会按配置路径去找副本：

- **找到副本** → 走 `/_image?href=...` 优化通道，**页面显示的是副本，不是 `public/` 里的**
- **找不到** → 退化成普通 `<img src="/assets/...">`，直接用 `public/` 里的文件

所以换 banner 图要**同时换两处**：

```
public/assets/desktop-banner/1.webp
src/assets/public/assets/desktop-banner/1.webp
```

判断某张图走的是哪条路：看渲染出来的 HTML。出现 `/_image/?href=...` 就是走了优化通道。

**2. Astro 的图片缓存**。缓存目录是 `node_modules/.astro/`，替换源文件它不会自动失效。症状是构建日志里出现 `(reused cache entry)`，`dist/` 里仍是旧图。

```bash
rm -rf node_modules/.astro     # 然后重新构建
```

构建成功时应该看到 `before: 207kB → after: 197kB` 这种，而不是 `reused cache entry`。`build-and-open.ps1` 和 `deploy-pages.ps1` 默认会清缓存。

### 别把 `.jpg` 直接改名成 `.webp`

这样没用：文件内容仍是 JPEG，只是扩展名变了。服务器按 `.webp` 发 `Content-Type`，图片管道解析失败，页面不显示。**必须真正转换格式**：

```bash
node -e "require('sharp')('x.jpg').resize({width:1920}).webp({quality:90}).toFile('x.webp')"
```

自查一个 `.webp` 是不是真的：

```bash
node -e "const b=require('fs').readFileSync('public/assets/desktop-banner/1.webp');
console.log(b.slice(0,4).toString()==='RIFF' ? '真 WebP' : (b[0]===0xFF&&b[1]===0xD8 ? '其实是 JPEG！' : '未知'))"
```

确认 `dist/` 里实际是哪张图（文件名是哈希，别靠猜）：

```bash
grep -o '_astro/[0-9]\.[A-Za-z0-9_-]*\.webp' dist/index.html | sort -u
node -e "require('sharp')('dist/_astro/1.XXXX.webp').metadata().then(m=>console.log(m.width+'x'+m.height))"
```
