# 01 快速开始与命令

## 环境要求

- Node.js **22.12 或更高版本**（Astro 7 的要求）
- pnpm（仓库使用 pnpm 11 的锁文件）

`pnpm-workspace.yaml` 里设置了 `nodeLinker: hoisted`。pnpm 默认用 junction 组织 `node_modules`，
在**中文路径 + 杀毒软件**环境下会静默失败（看起来装完了，实际只链接出十几个包，构建时报 `Cannot find module`），
所以改成复制模式。pnpm 10 以上不认 `.npmrc` 里的 `node-linker`，必须写在 `pnpm-workspace.yaml`。

## 第一次运行

```bash
git clone https://github.com/11408-prog/azur_blog.git
cd azur_blog
pnpm install
pnpm dev          # http://localhost:3000
```

内容分离（独立内容仓库）模式**默认关闭**，不需要再设置 `ENABLE_CONTENT_SYNC=false`。
只有在 `.env` 里写 `ENABLE_CONTENT_SYNC=true` 并配置 `CONTENT_REPO_URL`，才会在 `predev` / `prebuild` 里同步内容。

## 命令一览

| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | 本地开发，端口 3000，改了会热更新 |
| `pnpm build` | 完整构建，见下文"构建链" |
| `pnpm preview` | 预览 `dist/` 里的构建产物 |
| `pnpm check` | `astro check` |
| `pnpm type-check` | `tsc --noEmit` |
| `pnpm test` | 运行 `tests/` 下的测试，见 [10 排障](./10-排障与环境问题.md) |
| `pnpm lint` / `pnpm format` | Biome 检查 / 格式化，只作用于 `src/` |
| `pnpm new-post` | 新建文章（`scripts/new-post.js`） |
| `pnpm sync-music` | 同步本地 mp3，见 [06](./06-音乐播放器.md) |
| `pnpm check-fonts` | 检查构建产物里的字体引用 |
| `pnpm prepare-fonts` | 把 `ttf` 字体转成 `woff2`，见 [05](./05-字体与性能.md) |

### 构建链

`pnpm build` 依次执行：

1. `scripts/update-anime.mjs`（番剧页数据，`mode: local` 时基本是空操作）
2. `astro build`
3. `scripts/check-global-style-loading.mjs`（确认首页和关于页的样式都加载了）
4. `pagefind --site dist`（生成搜索索引）
5. `scripts/check-font-loading.mjs`（确认字体都能找到）

构建完成后产物在 `dist/`，约 65 个页面，耗时 1 分钟左右。
**构建前先停掉 dev**，两者会抢 `node_modules/.vite` 缓存。

> 第 3 步原来会因为站点部署在 `/azur_blog` 子路径而必然失败，并且强制要求关于页含有 GitHub 卡片，
> 已经修好：现在会自动去掉 `base` 前缀找文件，只有关于页源文件里真的写了 `::github{...}` 才要求渲染出卡片。

## 一键脚本（Windows）

| 文件 | 用途 |
| --- | --- |
| `start-site.bat` | 双击运行，内部调用 PowerShell 脚本 |
| `build-and-open.ps1` | 真正干活的脚本，也支持命令行参数 |

流程：**腾出端口 → 清 `dist/` 和图片缓存 → 构建 → 校验 → 起服务器 → 打开浏览器**。

```powershell
.\build-and-open.ps1                  # 完整构建后打开（最常用）
.\build-and-open.ps1 -Dev             # 开发模式，端口 3000
.\build-and-open.ps1 -PreviewOnly     # 跳过构建，直接看上一版成品
.\build-and-open.ps1 -KeepCache       # 增量构建（快；刚换过图片时别用）
.\build-and-open.ps1 -NoBrowser       # 起服务器但不开浏览器
.\build-and-open.ps1 -Port 5000       # 换端口
```

它会自动停掉占用端口的旧进程，并检查构建日志里有没有 `reused cache entry`（有就说明图片缓存没更新，会提醒你重跑）。

这个脚本直接调用 `node node_modules/astro/bin/astro.mjs build`，**不经过** `pnpm build` 的前后置脚本，
所以不会跑样式检查、Pagefind 和字体检查。需要搜索索引时请用 `pnpm build`，或者用 `deploy-pages.ps1`（它自己补跑 Pagefind）。

### 修改这两个脚本时的注意事项

- `build-and-open.ps1` 刻意写成**纯英文 + UTF-8 BOM**：终端代码页千奇百怪，中文输出很容易乱码，全 ASCII 就彻底免疫。修改时请保持纯英文。
- `start-site.bat` 里 `echo` 的文本**不能出现裸的 `>` 或 `<`**，cmd 会把它们当重定向符。
  曾经有一行带箭头的 `echo` 把 ps1 文件自己覆盖掉，导致双击后直接闪退。要写箭头就转义成 `-^>`。
- `.bat` 末尾有一个**无条件的 `pause`**，别删。`powershell -File` 在脚本报错时可能仍返回 0，没有 `pause`，任何错误都会变成"窗口闪一下就没了"。

## 终端差异

`VAR=value command` 是 bash 写法，**PowerShell 不认**，会报"无法将 `VAR=value` 项识别为 cmdlet"。

| 终端 | 判断方法 | 设置环境变量 |
| --- | --- | --- |
| PowerShell | 提示符形如 `PS C:\...>` | `$env:VAR="value"`（单独一行） |
| Git Bash / bash | 提示符是 `$` 或 `MINGW64` | `VAR=value command`（同一行） |

## 预览构建产物

**不能直接双击 `dist/index.html`**。页面里的资源是绝对路径（`/_astro/xxx.js`），用 `file://` 打开会全部 404，页面白屏。必须走 HTTP：

```bash
pnpm preview      # 然后打开 http://localhost:3000
```

`preview` 看的是 `dist/` 里的静态产物，**改了源码不会自动刷新**，要重新构建。日常开发请用 `pnpm dev`。
