# 10 排障与环境问题

## 页面没变化时，按这个顺序查

1. **改的是配置吗？** 确认改的是 `src/config/` 下正确的文件
2. **涉及图标吗？** 新增图标名要**重启 dev**（见 [04](./04-图标图片与横幅.md)）
3. **涉及图片吗？** 检查影子副本和 `node_modules/.astro` 缓存（见 04）
4. **以上都对还是没反应？** dev 跑超过 2 小时后，**文件 watch 可能失效**（改 `.md` 不生效），直接重启

重启 dev 能解决大部分"改了没反应"，先试这个再查代码。

见 [05 字体与性能](./05-字体与性能.md) 的排查顺序。

## 构建报错

| 报错 | 原因 | 对策 |
| --- | --- | --- |
| `Unable to locate "xxx:yyy" icon!`（挂在 `/404` 上） | 图标名不在本地 6 个集合里 | 见 04，换成存在的图标 |
| 整站构建失败，提示 `tags` 类型错误 | `tags: [408]` 被解析成数字 | 写成 `tags: ["408"]`（见 [03](./03-写文章.md)） |

| 检查脚本说 `About page is missing: rendered GitHub repository card` | 旧版脚本强制要求关于页有 GitHub 卡片 | 已修复，更新 `scripts/check-global-style-loading.mjs` |
| 检查脚本找不到 `/azur_blog/_astro/...css` | 旧版脚本没处理 base 前缀 | 同上，已修复 |
| `reused cache entry`，图片没更新 | Astro 图片缓存没失效 | 删 `node_modules/.astro` 重建 |
| `SAFE_DELETE_BULK_CONFIRM_REQUIRED` | 受限环境（AI 沙箱）里的批量删除保护 | 不是代码问题，见下文 |

## 测试

`pnpm test` 的命令是用 `&&` 把多个 `node --test` 和 `tests/crypto.test.mjs` 串起来的，**前面任何一步失败，后面的就不会运行**，包括加密测试。

2026-11-05 在未改动的代码上，`pnpm test` 有 3 项失败（和加密、部署都无关）：

- `Default image loading boundary`
- `Markdown AST enhancements`
- `Music player media loading boundary`

在修好之前，可以单独运行加密测试：

```bash
node --experimental-strip-types tests/crypto.test.mjs
```

这个测试直接导入真实的 `src/utils/crypto-utils.ts`，需要 Node 22.18 或更高（或者像上面一样加 `--experimental-strip-types`）。

## 环境问题（作者的 Windows 机器）

> 这一节是从旧站迁移过程中实打实踩出来的，**只对出现同样症状的环境有意义**。换了机器，先确认症状是否还在。

### schannel 损坏，git 的 HTTPS 不可用

```
schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030E)
```

- 症状：`git clone`、`curl.exe`、`Invoke-WebRequest` 都失败
- TCP 443 通、DNS 正常，**不是网络封锁**，是系统 TLS 栈坏了
- 绕过：用 Node 下载（走 OpenSSL 而非 schannel），或者让 git 走 OpenSSL（见 [08](./08-部署.md)）

### Node v25.2.1 在中文路径下的两个 bug

1. `fs.rmSync(dir, { recursive: true })` 会让进程崩溃，退出码 `0xC0000409`。绕过：手写 `unlinkSync` + `rmdirSync` 递归删除，或者用仓库里的 `rmrf.mjs`
2. `fs.cpSync` 复制含子目录的目录会报 `EIO, Access is denied`。绕过：用 PowerShell 的 `Copy-Item`

### pnpm 必须用 hoisted

见 [01](./01-快速开始与命令.md)。pnpm 10 以上不认 `.npmrc` 里的 `node-linker`，必须写在 `pnpm-workspace.yaml`。

### pnpm postinstall 被拒绝

```
Error: spawn EPERM   (esbuild postinstall)
```

包本身下载完成，不影响 esbuild 使用，但安装被打断会导致 `node_modules/.modules.yaml` 缺失。绕过：`pnpm install --ignore-scripts`。
实测补充：只要包本身齐全，`astro build` 照样能成功，所以先看包齐不齐。

## 在 AI 会话里工作的限制

如果让 AI 助手在受限沙箱里替你运行命令，要知道：

- 沙箱里的文件操作被一层安全代理包裹，**每个 `unlink` 约 0.5 秒**：删 1234 个文件的 `dist/` 花过 10 分 40 秒，而在自己的终端里 `Remove-Item -Recurse -Force dist` 只要 1~2 秒
- 沙箱还有批量删除保护（一次删超过 50 个文件就拦截），会让构建卡在最后一步的临时目录清理然后失败，产物其实已经生成好了
- 沙箱里 `child_process` 可能报 `EPERM`，所以 `pnpm build` 的前后置脚本可能起不来
- 在沙箱里跑 `deploy-pages.ps1` 会失败（不能新建 `dist/`、`.publish/`，pagefind 也会 `PermissionDenied`）

**结论：build、preview、部署和大批量删除，一律在你自己的终端里跑。**
