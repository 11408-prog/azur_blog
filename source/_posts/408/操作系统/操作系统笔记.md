# 死锁

## 死锁和饥饿的区别

死锁至少有两个进程，且都处于阻塞态

饥饿可能只有一个进程，可能处于就绪态，也可能处于阻塞态

## 安全状态与安全序列

- 安全状态：系统当前存在一种进程执行顺序，使得按这个顺序，每个进程都能获得它尚需的最大资源并顺利完成，最终所有进程都能结束（不唯一）

- 安全序列：安全状态放入执行顺序

处于安全状态，一定不会死锁。处于不安全状态，不一定会死锁。

## 四个数据结构

- Max 最大需求
- Allocation 已分配
- Need 还需要
- Available 系统剩余

Need = Max - Allocation

给进程排序时，Available要大于等于Need,否则不能分配

# 内存管理

分配与回收，内存保护，内存扩充

## 逻辑地址和物理地址

逻辑地址通过地址重定位转换成物理地址（真实位置）

## 装入方式

- 绝对装入：编译时确定物理地址。只适合单道
- 静态重定位：装入时一次性修改地址，之后不能移动
- 动态重定位：运行时才转换，靠重定位寄存器

| 对比项 | 绝对装入 | 静态重定位 | 动态重定位 |
|---|---|---|---|
| 核心做法 | 编译/汇编时直接生成绝对物理地址 | 编译时生成逻辑/相对地址，装入时一次性改成物理地址 | 程序始终保存逻辑地址，运行时由硬件转换成物理地址 |
| 物理地址确定时间 | 编译/汇编时 | 装入时 | 运行时每次访存时 |
| 地址转换由谁完成 | 编译器/程序员 | 装入程序 | 硬件（MMU、重定位寄存器） |
| 程序中的地址形式 | 物理地址 | 装入前为逻辑地址，装入后被改成物理地址 | 始终为逻辑地址 |
| 程序装入后能否移动 | 不能 | 不能 | 能 |
| 是否支持内存紧凑 | 不支持 | 不支持 | 支持 |
| 是否支持虚拟内存/分页分段 | 基本不支持 | 不支持 | 支持 |
| 硬件需求 | 一般无特殊硬件要求 | 一般不需要专门运行时重定位硬件 | 需要重定位寄存器/MMU 等硬件支持 |
| 适用场景 | 单道程序、早期系统、地址固定的嵌入式程序 | 早期多道批处理、无虚拟内存系统 | 现代操作系统 |
| 主要缺点 | 地址写死，灵活性极差，程序位置变化需重新编译 | 装入后不能移动，难以支持内存扩充和虚拟内存 | 需要硬件支持，实现较复杂 |
| 一句话记忆 | 编译时定死物理地址 | 装入时一次改完，之后不能移动 | 运行时硬件转换，可移动、支持虚拟内存 |

# 分页、快表与分段

## 分页

### 基本思想

把物理内存分成大小相等的块，叫页框/物理块。把进程逻辑地址空间也分成同样大小的块，叫页。

- 页大小=页框大小
- 进程的页可以离散地装入不连续的页框中
- 通过页表记录“逻辑页号 → 物理页框号”的映射

### 逻辑地址结构

| 页号P | 页内偏移W |

地址转换： 物理地址 = 页框号 * 页面大小 + 页内偏移

### 特点

- 没有外部碎片，只有少量内部碎片（最后一页可能填不满）

- 程序不必连续存放

- 便于实现虚拟内存

- 页表可能很大，需要多级页表

- 地址转换需要访问页表，可能增加一次或多次访存

### 为什么需要快表

加速访问

## 快表（TLB）

是一种高速缓存，专门缓存最近用过的页表项，通常位于 CPU 与内存之间，由硬件实现

### 有效访问时间（EAT）

EAT = 命中率 * 命中所需访问时间 + （1-命中率 * 未命中所需访问时间

## 分段

分段是按程序的逻辑结构把地址空间分成若干段，如代码段、数据段、栈段、堆段等。每段有段名和段号，每段从 0 开始编址，长度不同

### 逻辑地址

| 段号 S | 段内偏移 W |

### 分页和分段的区别

| 对比项 | 分页 | 分段 |
|---|---|---|
| 划分依据 | 按固定大小机械划分，与程序逻辑无关 | 按程序逻辑结构划分，如代码段、数据段、栈段等 |
| 大小 | 页大小固定，通常为 4KB 等 | 段大小不等，由逻辑意义决定 |
| 地址空间 | 一维逻辑地址空间（页号 + 页内偏移） | 二维逻辑地址空间（段号 + 段内偏移） |
| 对用户是否可见 | 对程序员透明 | 对程序员可见，段有逻辑意义 |
| 碎片问题 | 基本没有外部碎片，只有少量内部碎片 | 可能产生外部碎片，需要内存紧凑 |
| 共享与保护 | 不如分段方便，按页共享保护不够自然 | 便于按逻辑段共享和保护 |
| 动态增长 | 不方便动态增长 | 段可按逻辑需要动态增长 |
| 地址转换 | 通过页表：页号 → 页框号 | 通过段表：段号 → 段基址 + 段长 |
| 越界检查 | 页内偏移通常由页大小决定，页号查页表有效性 | 段内偏移需与段长比较，越界则中断 |
| 主要目的 | 提高内存利用率，减少外部碎片，支持虚拟内存 | 便于程序逻辑管理、共享、保护和动态增长 |
| 一句话记忆 | 分页是“物理上切块”，对用户透明 | 分段是“逻辑上切块”，对用户可见 |

# 虚拟内存

虚拟内存是一种内存管理技术，它让每个进程都以为自己拥有一个独立、连续且容量极大的内存空间，而实际上这个空间是由物理内存和外部磁盘共同拼凑并伪装出来的。

虚拟内存 = 物理内存 + 外存

## 局部性原理

- 时间局部性

- 空间局部性

## 虚拟内存的特征

- 多次性

- 对换性

- 虚拟性

虚拟内存的最大容量由CPU地址结构决定（32位——>4GB（2^32Bytes））
实际容量<=内存容量+外存容量

## 缺页中断的处理

*   **访问的页在内存？**
    *   **是** ➔ 直接访问
    *   **否** ➔ 缺页中断
        *   **有空闲块？**
            *   **否** ➔ 置换算法选一页 ➔ 被修改过？➔ 写回 ➔ 调入页面·改页表
            *   **是** ➔ 直接调入 ➔ 调入页面·改页表
        *   **调入页面·改页表** ➔ 重新执行该指令

缺页中断 = 内中断 （属于故障，是在指令执行期间产生和处理，一条指令可能产生多次缺页中断）

# 页面置换算法

页面置换算法是操作系统虚拟内存管理中的一种策略：当程序访问的页面不在物理内存中（发生缺页中断），而物理内存又没有空闲页框时，操作系统必须从当前已装入内存的页面中选择一个“换出去”到磁盘（交换区/外存），再把需要的页面“换进来”。这个选择淘汰哪个页面的规则，就叫页面置换算法。

## 最佳置换（OPT）

当发生缺页且需要淘汰一个页面时，选择未来最长时间内不会被访问的页面淘汰；如果某个页面以后不再被访问，就优先淘汰它。

缺页率 = 缺页次数/访问总次数

## 先进先出（FIFO）

换出最早进入内存的页

Belady异常：页框变多，缺页却更多了（因为FIFO会出现淘汰访问频率高的页的情况，这个异常只有FIFO算法会出现）

## 最近最久未使用（LRU）

用“过去”预测“未来”，需要替换时把最久没被访问的那个替换掉

实现开销大

## CLOCK算法（最近未用NRU）

LRU的近似实现

把物理内存中所有页框看作一个环形队列。发生缺页，且内存已满，需要淘汰一个页面时，指针开始扫表盘：
1.检查当前指针指向的页面：
如果它的访问位是 1：说明它最近被用过，不能淘汰。算法把它改成 0，然后指针往下走一格。如果它的访问位是 0：说明它最近没被用过，那就选中它进行淘汰，新页面装进来，访问位置 1，指针往下走一格。
2.指针就这么一直转圈扫描，直到找到一个访问位为 0 的页面为止。

# 高频考点速查

| 模块 | 核心公式 / 要点 | 模块 | 核心公式 / 要点 |
| :--- | :--- | :--- | :--- |
| **调度** | 周转 = 完成 - 到达；带权周转 = 周转 / 运行 | **分页** | P = [A/L]，W = A mod L，物理 = b·L + W |
| **HRRN** | 响应比 = (等待 + 服务) / 服务 | **快表** | EAT = α(t+m) + (1-α)(t+2m) |
| **饥饿** | SJF、优先级、多级反馈、SSTF | **置换** | 缺页率 = 缺页 / 访问；仅 FIFO 有 Belady |
| **信号量** | S < 0: \|S\| 个进程在等；前 V 后 P | **混合索引** | 每块存 块大小/块号长 个地址；逐级相乘 |
| **PV 顺序** | 互斥 P 放在同步 P 之后 | **位示图** | b = n·i + j；i = [b/n]，j = b mod n |
| **死锁** | 四条件；不死锁 m ≥ n(k-1)+1 | **磁盘** | T = 寻道 + 1/(2r) + 传输 |
| **银行家** | Need = Max - Allocation | **I/O** | 中断按字 · DMA 按块 · 通道按组 |
